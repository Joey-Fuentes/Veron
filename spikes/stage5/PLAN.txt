package veron-system 0.1.0
  group        system
  license      MIT
  recipe-sha   986642c3a23f68698e33244fa5036dc4c33caf14545b58c0dab391264d503af2

  source
    url        this repository
    sha256     n/a -- see [installs].digest, which pins every file
    signature  n/a -- the provenance is the commit that carries these files
    correspond none

  deps
    build        -
    link         -
    runtime      dinit
    optional_off -

  commands (literal; this is exactly what runs)
    [01] locale
         cwd  build/veron-system-0.1.0
         SHELL (declared) why=THE IMAGE HAD NO LOCALES AT ALL, AND IT WAS VISIBLE IN THE FIRST WORKING
SCREENSHOT. foot draws its own errors into its window, so the desktop rendered
correctly and then showed:

    'C' is not a UTF-8 locale, and failed to find a fallback

foot tries C.UTF-8 and then en_US.UTF-8 (main.c:455) before giving up, and
neither existed: there was no /usr/lib/locale directory in the image.

WHY IT IS GENERATED RATHER THAN PINNED. localedef and the C locale source are
both already in the stage-4 sysroot -- glibc puts them there -- so this needs
no new artifact, no mirror upload and no version to track. The output is 428K
for one locale.

--no-archive GIVES A DIRECTORY, NOT locale-archive. The archive form is a
single binary blob that a reader cannot inspect and that files.tsv records as
one opaque entry; a directory records as the twelve LC_* files it is. For a
system whose manifest is the point, the directory is the right shape.

C.UTF-8 AND NOTHING ELSE. It is the locale glibc guarantees semantically --
byte-order collation, ASCII semantics -- with UTF-8 encoding, which is exactly
what a terminal needs and nothing more. Adding language locales is a decision
about what the system claims to support, and belongs with the person who wants
one.

WHAT THIS DOES NOT FIX: xkbcommon also reports "No Compose file for locale",
which comes from libX11's /usr/share/X11/locale tree. There is no X11 here, so
dead-key composition stays unavailable. That is a separate absence and not a
locale one.

         | set -eu
         | mkdir -p "dest/veron-system/usr/lib/locale"
         | # THE CHARMAP IS GZIPPED AND localedef IS GIVEN THE PLAIN ONE. glibc ships
         | # /usr/share/i18n/charmaps/UTF-8.gz, and rather than depend on how this
         | # localedef handles compression -- which differs between builds and is not
         | # worth discovering in CI -- it is decompressed first and passed by path.
         | gzip -dc /usr/share/i18n/charmaps/UTF-8.gz > UTF-8.charmap
         | localedef --prefix="dest/veron-system" --no-archive -f UTF-8.charmap -i C C.UTF-8
         | rm -f UTF-8.charmap
         | ls "dest/veron-system/usr/lib/locale/C.utf8/LC_CTYPE" >/dev/null
    [02] install
         cwd  build/veron-system-0.1.0
         argv ["sh", "-c", "mkdir -p \"dest/veron-system\" && cp -a /packages/veron-system/files/. \"dest/veron-system/\""]
    [03] install
         cwd  build/veron-system-0.1.0
         argv ["sh", "-c", "mkdir -p \"dest/veron-system/var/lib/chrony\""]

    correspond none

  deps
    build        xz
    link         -
    runtime      -
    optional_off right_only, slim

  commands (literal; this is exactly what runs)
    [01] unpack
         cwd  build/tzdb-2026c
         SHELL (declared) why=tar IS busybox HERE AND busybox tar HAS NO --use-compress-program. The first
version of this step passed that flag, which GNU tar supports and this system's
does not:

    tar -> /usr/bin/tar
    /usr/bin/tar is a symlink -> busybox

busybox's own help lists --lzma and --exclude and no --use-compress-program, so
the flag was parsed as a filename and tar printed its usage. Piping is what
busybox offers instead: its -f documentation reads "-f FILE  Name of TARFILE
('-' for stdin/out)".

xz IS THE REAL ONE BY THEN, NOT busybox's. The sysroot ships /usr/bin/xz as a
symlink to busybox, whose xz applet is a minimal decoder that does not know
lzip. The xz PACKAGE installs a real 5.8.3 binary over that path and is
declared in deps.build, which puts it at rung 20 against this package's 40.

    [02] install
         cwd  build/ca-certificates-3.126/nss-3.126
         SHELL (declared) why=The conversion is inlined rather than shipped as files/certdata2pem.py because
a step cannot reference the recipe's own files/ directory portably: the build
runs with cwd=$S, so a relative path does not resolve, and an absolute one puts

         | import base64, re, sys
         | 
         | src, dst = sys.argv[1], sys.argv[2]
         | text = open(src, encoding="utf-8", errors="replace").read()
         | 
         | # Records begin with CKA_CLASS. The DER and the trust decision are SEPARATE
         | # objects joined by CKA_LABEL -- see the deferral for why conflating them
         | # ships roots Mozilla has distrusted.
         | certs, trusted = {}, set()
         | for b in re.split(r"\n(?=CKA_CLASS )", text):
         |     m = re.search(r'CKA_LABEL UTF8 "([^"]*)"', b)
         |     if not m:
         |         continue
         |     name = m.group(1)
         |     if "CKO_CERTIFICATE" in b:
         |         v = re.search(r"CKA_VALUE MULTILINE_OCTAL\n(.*?)\nEND", b, re.S)
         |         if v:
         |             certs[name] = bytes(int(o, 8)
         |                                 for o in re.findall(r"\\([0-7]{3})", v.group(1)))
         |     elif "CKO_NSS_TRUST" in b:
         |         # SERVER AUTH ONLY. A root trusted for e-mail or code signing is not
         |         # one a browser may accept for TLS.
         |         tr = re.search(r"CKA_TRUST_SERVER_AUTH CK_TRUST (\w+)", b)
         |         if tr and tr.group(1) == "CKT_NSS_TRUSTED_DELEGATOR":
         |             trusted.add(name)
         | 
         | # SORTED so the bundle is byte-identical between runs.
         | keep = sorted(n for n in certs if n in trusted)
         | if not keep:
         |     sys.exit("certdata2pem: no trusted roots -- refusing to write an empty bundle")
         | 
         | # UTF-8, not ASCII: the comment carries upstream's CA name and at least one
         | # contains a Hungarian o-double-acute. The certificate data itself is base64.
         | with open(dst, "w", encoding="utf-8") as out:
         |     for n in keep:
         |         b64 = base64.standard_b64encode(certs[n]).decode("ascii")
         |         body = "\n".join(b64[k:k + 64] for k in range(0, len(b64), 64))
         |         out.write("# %s\n-----BEGIN CERTIFICATE-----\n%s\n-----END CERTIFICATE-----\n"
         |                   % (n, body))
         | sys.stderr.write("certdata2pem: %d certificate(s), %d trusted for TLS server auth, %d written\n"
         |                  % (len(certs), len(trusted), len(keep)))
         | CERTDATA2PEM
